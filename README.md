## 当前版本

**配图支持**：心事和来信均可附一张 JPG / PNG / WebP（原图最多 8 MB），浏览器自动缩小至最长边 1400px、压缩后数据不超过 700,000 字符。仍需填写正文。心事图片可预览、替换、移除，跟随本机草稿恢复和发布预览，并作为列表封面；来信图片默认私密，授权公开包含配图，撤回会清除正文、配图及回复。

已有项目请运行 [migration-images.sql](supabase/migration-images.sql)，再刷新页面。图片以压缩数据随记录保存到数据库，继承现有 RLS，没有公开图片 URL；适用于当前小型个人站。图片会占用数据库及本机草稿容量，未来大量配图需迁移到私有对象存储。数据库未升级时纯文字仍可正常使用，带图保存会保留内容并提示升级。

配图版本本地共 16 项测试通过；包括草稿配图恢复、处理失败及取消、私密图片权限、撤回图片清除。真实浏览器选图和生产数据库迁移需在上线环境核验。

本次新增六项交流功能。**已有 Supabase 项目须先运行 [migration-community.sql](supabase/migration-community.sql)**，才能启用撤回、未读计数、交流计数和全文搜索。手机导航、分享卡片和直达文章链接无需数据库迁移。新项目直接执行最新版 `schema.sql`，无需再执行旧迁移。代码发布不代表数据库已升级。

- **撤回来信**：登录后在“我的来信”点撤回并确认；数据库清除原文、回复并撤销公开，保留已撤回记录，站主不能恢复。站主收起的来信，发信人仍可查看并撤回。撤回无法收回他人先前保存的副本。
- **未读提示**：“收到的来信”旁显示未读数；登录、回到页面、前台每分钟刷新。点击“标为已读”或保存非空回复后消除未读；打开列表不会自动清空。升级前的来信没有阅读记录，初始视为未读。
- **交流状态**：文章显示公开交流数和已回复数，留言显示“等待回复 / 已回复”，回复用另一张信笺展示。私密、收起、撤回的来信不计入公开数量；文章收起后交流也不公开。
- **手机导航**：600px 以下保留六个图标，只显示当前章节的文字，保留屏幕阅读器标签及键盘操作。
- **分享卡片**：公开心事可生成标题、摘要和直达链接，复制整段文字或使用设备系统分享。链接格式为 `?journal=文章ID#journal`；即使文章不在首页列表，也会单独加载。草稿、收起和不存在的文章不展示正文。GitHub Pages 没有服务端逐篇社交预览，因此聊天软件自动抓取的预览卡片仍由平台决定；本站提供的是站内卡片和可复制分享文字。
- **内容搜索**：标题、全文和中文分类均可搜索，可叠加分类并继续分页。数据库只返回公开且未删除的心事；百分号等字符按普通文字匹配。

本次验证：14 项本地测试通过，包含数据库权限、撤回擦除、公开计数、未读、搜索、直达链接、分享文字和已有草稿保护。生产数据库升级和真实手机视觉验收需在部署环境完成。

网站已发布到 GitHub Pages，并已配置 Supabase 项目、建立数据表和权限规则。公开内容接口已确认可访问，未登录用户直接读取私密来信会被数据库拒绝。

站主需要使用已验证的邮箱账号，并在 Supabase SQL Editor 中完成站主指定；注册本身不会获得编辑权限。登录后出现 **管理我的网站**，才表示该账号具备站主权限。

## 账号与使用方式

主页面采用横向章节切换：底部图标依次进入首页、关于我、心情、心事、给你的信与来信。手机可左右滑动切换，章节里的长内容仍可上下滚动；每章保留阅读位置。导航支持左右方向键、Home / End，表单输入和弹窗不会触发翻页，浏览器前进、后退及 `#about` 等地址锚点仍可使用。暂停动效或系统减少动态效果时直接切换。实现位于 `chapters.css`、`chapters.js`；JavaScript 不可用时回退为原本的纵向页面。

底部导航使用主界面的米白信纸、青灰图标和 LimeHand 手写中文；当前章节以浅青绿底色与暖橙短线标记，键盘焦点使用细虚线，保持与首页标题和信纸卡片的风格一致。

| 身份 | 可以做什么 |
| --- | --- |
| 未登录访客 | 浏览个人介绍、公开心事和已公开的来信 |
| 注册并登录的访客 | 浏览公开内容，提交评价、建议和提问，查看自己寄出的来信与回复 |
| 站主 | 编辑页面文字和口袋便签，管理心事、草稿与回收站，回复来信并决定是否公开 |

### 注册与登录

点击网站左下角 **登录 / 注册**，选择注册账号，填写邮箱和密码（至少 10 位），通过邮件验证后登录。忘记密码时可从同一窗口申请重置邮件。邮箱跳转地址和邮件服务设置见 [接入说明](supabase/SETUP.md)。

### 管理我的网站

站主登录后，点击左下角 **管理我的网站**：

- **编辑网站文字**：选择文字位置，修改后保存，所有访客都能看到更新。
- **写一篇心事**：编辑时自动暂存到当前浏览器，重新打开同一篇心事可恢复；关闭或刷新前提示未保存修改。勾选公开后先预览，再确认发布；不勾选则保存为云端草稿。
- **管理心事 / 草稿**：编辑已有心事，或移入回收站；恢复时默认存为草稿。首次写入日期保留，修改时间自动更新。
- **收到的来信**：阅读评价、建议和提问，添加回复，选择公开或撤回公开；收起的来信可以恢复。
- **把原有三篇手记导入为草稿**：保留最初的三篇静态手记，逐篇修改后再公开；重复导入不会覆盖已有修改。

接通数据库后，心事区以数据库中的已公开内容为准。如果暂时为空，可新写一篇，或先导入原有手记；导入时间会成为这些手记的写入日期。

## 换成自己的内容

接通后台并指定站主后，登录网站，点击左下角 **管理我的网站** 即可编辑文字与心事，不必再改源码。以下是未接通后台时的静态初始内容位置：

- **站名、自我介绍、访客信：** 修改 `index.html`。相框图片位于 `assets/profile-portrait.jpg`，采用完整显示方式，可直接替换图片。
- **手记正文：** 修改 `script.js` 中的 `articles` 对象，同时更新 `index.html` 对应卡片的标题与摘要；卡片的 `data-article` 与对象键名需要一致。
- **心情文案：** 修改 `script.js` 中的 `feelingCards`；默认显示的第一张心情也需同步修改 `index.html`。
- **图片：** 替换 `assets/summer-sky.jpg`，或修改 `style.css` 中 `.hero-picture` 的图片路径。
- **颜色和排版：** 基础颜色位于 `style.css` 开头的 `:root`；个人版布局和动画位于 `personal.css`。

现有第一人称文案是可编辑初稿，公开展示前请按个人真实想法调整。网站未填写虚构的联系方式或社交账号。

## 动画与可访问性

首页开场使用提供的纸飞机角色插画：透明素材沿天空滑入、轻微抬头后飞出，约 2.8 秒结束；直接呈现首页背景，不再使用全屏信纸、旋转星形或加载线。滚动离开首页、按 Tab / Escape、暂停动效或设置减少动态效果时会跳过。实现位于 `arrival.css` 和 `arrival.js`，原始参考图保留在 `assets/stickers/arrival-plane-reference.jpg`。

四个模块使用柔和的角色切入转场：关于我（纸飞机漂入）、心情（拍照轻晃）、手记（旅行漂浮）、访客信（送信轻跃）。角色以小幅动作在模块边缘浮现，约 2.3 秒后淡出，不使用横扫幕带，也不改变正文透明度。图片已生成透明 WebP，降低饱和度并与页面颜色混合；原始 JPG 仍保留在 `assets/stickers/`。快速切换会取消上一段，浮层不占排版空间、不拦截点击。暂停动效、系统减少动态效果或切到后台时立即停止。实现位于 `chapter-entrances.css` 和 `chapter-entrances.js`。

标题与导航参考活动 UI，使用手写中文、卷曲英文、错落字形和星形卷线装饰；正文保留清晰的阅读字体。样式位于 `lettering.css`。本地托管的 Henny Penny 与 ZCOOL KuaiLe 字体遵循 SIL Open Font License，许可证位于 `assets/fonts/`。字体已按本站内容精简，添加新中文标题时需补充相应字形，否则会使用后备字体。并非游戏原版定制字形。

- 纸飞机开场自动结束，按 `Tab` 或 `Escape` 可以跳过。
- 标题与导航错落入场，内容进入视野时轻量浮现。
- 使用原生 CSS、Web Animations API 和 IntersectionObserver，无第三方动画库。
- 右下角可暂停动效，遵循系统的 `prefers-reduced-motion` 设置。
- 弹窗支持键盘关闭，按钮提供焦点样式与必要的辅助标签。
- JavaScript 不可用时，页面主体仍可阅读，交互功能需要 JavaScript。

## 内容与隐私

网站文字、心事与来信保存在 Supabase。口袋便签现在属于站主内容，访客不能编辑。旧版本浏览器本地便签不会自动上传，可由站主手动复制到文字编辑器。

来信默认仅发送者和站主可见。发送者选择“允许公开”后，站主才可以公开昵称、正文与回复；授权本身不会直接发布。选择“仅给你看”的来信不能公开，站主也不能修改发送者的授权或原文。旧来信视为未授权，升级时撤回其公开状态并保留内容。公开接口不返回账号 ID 或邮箱。

心事的本机暂存按账号和文章分开，保存在当前浏览器的 localStorage，不能跨设备恢复；清除浏览器数据会丢失暂存。保存到云端后清理对应暂存，存储失败会提示。暂存不是加密保险箱，共用设备应保存后清理；正式心事与回收站仍由数据库权限保护。编辑云端已有心事时检查版本，避免直接覆盖另一处的新修改。

**已有项目升级**：在 Supabase SQL Editor 执行 [来信授权升级脚本](supabase/migration-public-consent.sql)。未升级时新版页面会暂停寄信和公开操作，避免承诺的授权规则没有数据库保护。新项目直接运行最新 `schema.sql`。

**文章交流升级**：完成公开授权升级后，执行 [心事交流升级脚本](supabase/migration-journal-comments.sql)。原有来信保留；与文章关联的来信只在对应心事中公开，普通来信继续显示在来信墙。文章撤回公开或移入回收站时，其公开交流也停止对外展示。访客可在“我的来信”查看自己提交的内容与回复，站主在“收到的来信”中审核并通过“查看关联心事”回到原文。文章交流每页 20 条，支持继续加载。

GitHub 备份的是代码，**不包含数据库中的新内容**。心事与来信需要另行通过 Supabase 备份或导出。

## 心事加载优化

### 不依赖 Supabase 的公开阅读

访客优先阅读随网站部署的 `public-snapshot.js`：公开心事、博客、配图和网站文案。搜索、分类及文章分享链接也使用这个副本，不等待 Supabase。站主身份确认后，管理与编辑仍读取数据库；登录、来信和交流仍需要连接 Supabase，静态阅读没有解决这些服务的网络问题。

运行 `npm run export:public` 更新副本，然后提交并部署网站。导出仅使用前端 publishable key，通过匿名 API 严格筛选 `published=true`、`deleted_at=null`；不读取来信、用户表、草稿或回收站。导出失败会保留原副本，不覆盖为空列表。Windows 导出使用 PowerShell 的网络配置。

数据库中的发布、修改、收起、删除不会自动更新静态副本，必须重新导出并部署。公开副本会进入 Git 历史，删除网站上的文章也不代表历史副本消失；只发布适合长期公开的内容。当前没有自动同步任务。

“最近心事”和列表先读取短摘要，不在列表请求中传输 Base64 图片。进入可见区域后单独读取封面，每次最多两张；列表视图不请求封面。打开心事时重新检查公开状态、按需读取全文，配图单独加载，图片失败不阻塞正文。编辑前读取完整记录以保留原配图。

封面失败可点击“重试配图”，不会打断正文阅读。切换到其他章节时停止发起排队中的封面请求，返回后再按可见位置加载。

等待时显示加载占位；失败时显示重试入口，不再把静态示例误显示为云端内容。没有配置后端时仍保留示例。未增加持久化内容缓存，因此已收起内容不会从本机缓存重新展示。

已有数据库在 SQL Editor 执行 [migration-journal-loading.sql](supabase/migration-journal-loading.sql) 即可启用 120 字摘要、配图标记及全文搜索；不修改已有文章。未升级时兼容旧接口，排除图片字段，但旧接口仍会传输完整正文。新项目 `schema.sql` 已包含该升级。这些改动减少传输量，不保证改善运营商到 Supabase 的连接时间。

## 博客栏目

博客与心事分开，沿用天空与奶油信纸风格，章节导航新增「博客」。支持技术 / AI / 随笔分类、标签、标题／摘要／正文／标签搜索、分页阅读，以及每篇一张封面图。

- 访客无需登录即可阅读已发布文章；分享链接形如 `?blog=文章ID#blog`，可以直接打开原文。
- 站主登录后可写文章、编辑、保存云端草稿、预览后确认发布、移入回收站，以及恢复为草稿。数据库 RLS 限制普通账号的写入权限，私密草稿不进入公开搜索。
- 编辑已有文章时检查版本，避免直接覆盖其他窗口的新修改。关闭未保存的编辑器会提醒，保存失败会保留当前输入；**博客暂不提供本机自动暂存**，长文请及时保存云端草稿。
- 正文目前为纯文字，保留换行和缩进，不解析 Markdown 或 HTML；博客暂未接入心事的交流模块。

**已有项目启用**：在 Supabase SQL Editor 运行 [migration-blog.sql](supabase/migration-blog.sql) 全文，再刷新页面。可重复执行，不改动既有心事、账号和来信。新项目直接运行最新 `schema.sql` 即可。无需另建 Supabase 项目或修改公开配置。

代码更新后需部署页面才能供线上访客使用；在管理界面保存文章直接写入 Supabase，不需要重新部署。博客数据也需要单独备份，Git 只备份代码。
